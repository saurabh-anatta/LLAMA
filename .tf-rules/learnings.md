[chat] Horizon's `.section-background` class is `position: absolute; inset: 0; z-index: -2` (base.css). It's meant for a SEPARATE sibling `<div class="section-background color-X">` that sits behind content — NOT for the section's main element. Adding `section-background` to a `<section>` makes the whole section absolute-positioned and overlap the previous section. For a custom section's background color, apply `background-color: var(--color-background)` directly in the section's `{% stylesheet %}` instead.
[chat] In Horizon, `--color-background` (and other `--color-*` vars from color-schemes.liquid) already contain the full `rgb(...)` expression. Use `var(--color-background)` directly — do NOT wrap in `rgb()`. The raw channels are exposed separately as `--color-background-rgb` for use with `rgb(var(--color-background-rgb) / opacity)`.
[chat] Horizon's header switches between horizontal menu and hamburger drawer based on `data-menu-style` set by JS (`assets/utilities.js` setHeaderMenuStyle). It becomes `'drawer'` when `isTouchDevice()` OR the overflow-list reports `minimum-reached` (visibleElements < minimum-items, default 2). Never apply `position: absolute` to `.header__column--center` — it removes the column from grid flow, the overflow-list inside measures zero available width, marks all items as overflow, and forces the entire desktop header into mobile/hamburger layout. Use the native grid `1fr auto 1fr` for centering instead.
[chat] Horizon's `filters` block on a collection page renders three things together: the desktop horizontal `.facets-block-wrapper`, the mobile `.facets-toggle`, AND the `<dialog-component id="filters-drawer">`. Setting `"disabled": true` in template JSON removes ALL of them — including the drawer, so any custom button using `on:click="#filters-drawer/showDialog"` silently does nothing. Keep the block enabled and hide the unwanted UI via CSS instead (`.collection-wrapper > div.facets-block-wrapper, .collection-wrapper > div.facets-toggle { display: none !important }`). The `<dialog-component>` is not a `<div>`, so this CSS leaves the drawer intact.
[chat] To trigger Horizon's filter drawer from a custom element, use `on:click="#filters-drawer/showDialog"` (no leading `id=` prefix, just the hash). The `dialog-component` web component (`assets/dialog.js`) listens for these via Component's event-delegation, so the trigger element doesn't need to be inside the dialog-component itself.
